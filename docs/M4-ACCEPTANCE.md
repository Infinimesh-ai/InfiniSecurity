## 后端选型定稿(PLAN 开放问题 4 结案)

VM 实测:`/` 与 `/home` 都是 **ext4,单分区,无 LVM、无 btrfs**,
未安装 restic/borg,硬链接可用。因此内置后端定为**硬链接增量快照**
(rsnapshot / Time Machine 的做法):与上一份快照内容相同的文件直接建
硬链接,变了的才复制。每份快照只占增量空间,而每份都是完整可浏览的
目录树。不引入外部依赖,装机即可用。

**诚实边界写在模块头也写在告警里:硬链接快照与源数据同盘同文件系统。**
它防误删误改,防不了磁盘故障、文件系统损坏、整机丢失。真正的 3-2-1
需要离机副本——所以 `backup status` 把"有没有离机副本"作为常驻检查项,
缺了就一直告警。事故那天救回数据靠的是宿主机上的 VMDK 冷副本,
不是同盘的任何东西,这条不能让用户误解。

## 验收结果

| # | 验收项 | 结果 |
|---|---|---|
| ① | 无快照 / 无离机副本 / 从未演练 三项缺失全部告警 | PASS ×3 |
| ② | 首次快照:目录建立、内容一致 | PASS ×3 |
| ② | 符号链接原样保留,不跟随(未把 /etc 内容拷进快照) | PASS ×2 |
| ③ | 增量快照:只复制改动的 1 个文件,其余硬链接复用 | PASS ×2 |
| ③ | 未改动文件与上一份共享 inode;改动文件是独立副本,**旧快照未被污染** | PASS ×3 |
| ④ | `drill` 从快照**实际恢复**到目录并逐文件验哈希,报告全部一致 | PASS ×2 |
| ⑤ | 演练记录消除"从未演练"告警;离机副本告警仍在催 | PASS ×2 |
| ⑥ | 篡改快照内容后,演练必须报哈希不符(不能报通过) | PASS |

第 ③ 组里"改动文件必须是独立副本"这条是硬链接增量最容易写错的地方:
一旦把改动后的文件硬链接到旧快照,写入会**同时改写历史快照**,备份就
悄悄变成了单副本。单测与 VM 验收都盯着 inode 比对这一点。

## 首轮失败与修正

- **实现缺陷**:演练的恢复目录建在 `/tmp`,而 `ProtectSystem=strict` 下
  /tmp 对 daemon 只读,演练直接报 EROFS。改到 `/var/lib/infinisec/drill`
  (StateDirectory,在 ReadWritePaths 内)。
- **测试缺陷两处**:① 扫快照目录时把 `~/Documents` 等默认保护目录的
  快照也扫了进来,比对的根本不是同一个对象;② 判断"有没有跟随符号
  链接"时用了 `-d link-out/ssl`——那会顺着链接走到真的 `/etc/ssl`,
  是符号链接的正常语义。正确做法是看快照里存的是不是链接本身
  (`readlink` 结果)。

## 已知边界

- 快照由 `infsec backup now` 手动触发;定时守护(systemd timer)留到 M7
  与通知一起做,现在的默认部署不会自动快照。
- 保留策略固定保留最近 10 份,尚未按策略可配。
- 只快照本用户 home 下的保护目录:home 之外的保护路径(如 `/srv/data`)
  当前不进快照仓库,因为隔离区/快照必须与源同文件系统才有原子性保证。
- 硬链接快照不保留属主与 xattr(与隔离区的跨设备回退同源的局限)。
