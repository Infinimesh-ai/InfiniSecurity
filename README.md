# InfiniSecurity

**Agent 的最后一道防线** —— 用杀毒软件的原理,在操作系统层面拦住 AI Agent 的
破坏性操作;拦不住的,帮你把数据完整地找回来。

## 为什么存在

2026-07-29,同一台开发机上发生过一次真实事故:一条 `rm -rf / --no-preserve-root`
在一次设计错误的验收测试中被真实执行,删掉了 InfiniCode 全部代码(含 .git)、
SparkClaw_Work 与 `~/.claude` 记忆(复盘见
`../InfiniCode/docs/LESSONS_2026-07-29_rm-rf_incident.md`)。

那次事故证明了两件事:

1. **应用层的审批网关不管做得多对,只要危险字符串还能到达 exec,就不存在
   "最后一道防线"。** 最后一道防线必须在内核边界上,独立于 Agent、独立于
   被测系统、独立于测试脚本。
2. **拦截总有失手的一天,恢复能力决定失手的代价是"回滚十分钟"还是"全部归零"。**
   那天靠一份手写 SOP 和 VMDK 冷副本做到了零净损失,连删除瞬间未提交的
   2242 行代码都找了回来——这套流程(`../InfinCode/DevU24-deletion-recovery-SOP.md`)
   应该成为产品能力,而不是一个人的一次幸运。

## 杀毒软件原理 → Agent 防御的映射

| 杀毒软件 | InfiniSecurity |
|---|---|
| 特征码库 | 破坏性命令签名(`rm -rf /`、`dd` 写块设备、`mkfs`…)→ **无条件硬拒绝** |
| 实时防护(on-access) | 内核层拦截 `execve` / `unlink` / `rename` / `truncate` |
| 启发式 / 行为分析 | 灰区操作(删保护目录内容等)→ 挂起,交**本地二审 Agent**(Claude / Codex)复核 |
| 勒索软件行为防护 | **爆发检测**:进程树短时间大量删除 → 立即 SIGSTOP 冻结全进程树 + 告警 |
| 隔离区 | 放行的删除也不真删,先移入隔离区,N 天内可 `infsec restore` |
| 系统还原点 | 保护目录定期快照 + 3-2-1 备份守护,恢复演练是常规命令不是灾难现场 |
| 急救盘(Rescue Disk) | **引导式取证恢复**:把事故 SOP 产品化,止损→只读取证→恢复→验证→回迁 |
| 信誉系统 / 云查杀 | **备份态感知**:远端 git 同步良好的项目内操作获得更高信任等级(T1 免二审),无远端/跨目录则收紧(T2/T3) |
| 信任区 / 白名单 | `build/`、`node_modules/`、`/tmp` 等低价值路径直接放行,只留审计 |
| 自我保护(anti-tamper) | 保护目录集由防御系统统一管理、Agent 只读;策略、审计、隔离区与 infsec 自身都在保护集内;**默认 root 部署**,与被监督用户隔一道特权边界(事故中 root 属主的 Docker 幸存即证据)——失控进程关不掉、也杀不掉防御系统 |

## 两大支柱

### 支柱一:拦截(事前)

```
Agent 进程发起 syscall(execve / unlinkat / rename / O_TRUNC …)
        │
        ▼
 ① 签名层:命中破坏性签名?──是──▶ 硬拒绝(EPERM),仅人工带外解锁
        │否
        ▼
 ② 行为层:目标在保护目录内?──是──▶ 挂起 → 二审 Agent 复核 → allow / deny
        │否                          (二审超时或不可用 → fail-closed 拒绝)
        ▼
 ③ 放行 + 审计(删除类操作进隔离区,不真删)
     ⨯ 全程爆发检测:删除速率异常 → 冻结进程树
```

拦截的宽严由三个维度合成:**备份态**(T0–T3:远端同步良好 → 免二审放行;
无远端 → 强制二审;跨目录 → 独立跨界风控模型,默认双 Agent 会签;
家目录级递归删除 → 任何配置都必然拦截)× **路径语义**(S0 可再生物直接
放行,S2 未提交内容从严,S3 秘密先快照,S4 基础设施近乎硬拒)×
**发起者情景**(interactive / autonomous / ci / server 各配不同风控模型)。

效率与安全同时成立的关键:操作级合并判决(`rm -rf` 的千次 unlink 只审一次)、
判决缓存、意图预授权(`--may-delete`,越界即最强风险信号)、
边缘场景的异步复核——全部机制不反转 fail-closed 方向。

二审 Agent 的权力是**单向的**:它只能裁决灰区,不能推翻签名层的硬拒绝;
它自己以只读、无网络、无执行权限运行——复核者不能成为新的攻击面。

### 支柱二:恢复(事中 + 事后)

- **使恢复成为可能(事前埋点):** 隔离区、定期快照、审计日志精确记录删除边界。
- **应急止损(事中):** 爆发检测冻结进程树;`infsec panic` 一键停写、保全现场。
- **引导式取证恢复(事后):** `infsec recover` 把经过实战验证的 SOP 编码为
  带门禁的向导——每一步自动验证(三层只读、哈希清单、恢复分级),
  帮助没有取证经验的人也能安全地挽回损失。
- **恢复对象不限于本机 Linux:** 企业虚拟化镜像(VMware/ESXi 的 VMDK 与
  VMFS、PVE 的 qcow2/LVM/ZFS、Hyper-V 的 VHDX)与 Windows(NTFS)/
  Mac(APFS)物理盘都在矩阵内——镜像访问层统一转成只读块设备,
  文件系统层编排成熟取证工具(TSK、photorec、ext4magic 等)。

实现语言:拦截与恢复统一 Rust(选型对比见计划第 4 节)。

## 诚实边界

这不是银弹,以下场景明确不设防,靠其余机制兜底:

- root / 内核态的攻击者可以直接关掉本系统;**给 Agent 配免密 sudo 等于
  亲手拆掉特权边界**——安装时会检测并常驻告警,但拦不住你坚持这么配;
- M1 的进程树包裹模式管不住未被包裹的进程(系统级 eBPF LSM 在后续里程碑);
- 覆盖写(`> file`、写零)在 truncate 门上线前不设防;
- 二审 Agent 同样会幻觉——它降低单次误判概率,不把它降到零;
- 恢复能力受物理规律约束:被覆盖的块无法找回,快照与备份才是恢复率的上限。
